# 双 ROI 裁剪部署评审（2026-10-08）

已在 PYNQ-Z2 验证原模型 SVH1 实现，核 100MHz。旧界面手部入口使用 ARM 全模型整数推理，曾测得手检8954ms、单ROI关键点7543ms；这不是 SV 核速度。现已加入 `--hand-pl`、独占 RP 的 worker 请求、开机 SVH1 对拍、默认手部启动与结型部分重配置入口，无手部 CPU 回退。

## ARM 裁剪现状

板上 OpenCV4.5.4 的 warpAffine 与之前视频验证的 OpenCV5.0 accurate 实现不同。直接替换时，两个真实 ROI 有14044个通道字节不同，最大差5。保留原输入契约的 C++ 实现明确复现 float 坐标和取整，随后通过 NEON 四像素并行、提前计算坐标、零边界快速填充及半整数邻域精确补算加速。128组随机/真实/边界 ROI 全字节一致，已在 ARM 执行。

最终一次无 HDMI/UI 竞争的板端分段平均：双 ROI裁剪24.486ms；输入同步、PL、输出同步合计63.057ms（其中核61.514ms，约6128651周期）；两个原模型末端均值/FC共2.848ms。完整后端调用平均94.378ms，包含坐标变换与Python组织。原精确标量版本完整后端128.799ms。该测量不含摄像头采集、跨进程传帧、界面绘制，不能宣称14fps。静态双手测试图连续8次跟踪均输出两手，不是新独立标注精度测试。

## PL 方案及实施边界

当前 SV 核不包含 ROI裁剪/缩放。增加独立的 AXI读图→两行/必要邻域缓存→双线性缩放→RGBX写入核输入地址的模块，才能在 PL 完成裁剪；仅在 PS 调整 DMA 地址不能完成缩放。

固定两个224×224输出，每个ROI的(cx,cy,side)由PS跟踪器提交。裁剪核必须处理图像边界零填充、BGR/RGB通道顺序与原坐标约定。1像素/拍的理想输出量为100352拍，即100MHz下1.004ms，但这只是理想吞吐下界，未含DDR、缓存命中、通道计算与控制，不是可承诺的实测耗时。应先建完整AXI模型，测源图读取量/突发效率/双ROI总周期，并证明输出契约；随后才综合、审计资源与实现。

只把裁剪从24.5ms降到几毫秒，并不自动满足整机14fps：现有核约61.5ms，加2.8ms末端和缓存维护后余量很小。必须同时消除重复整帧复制、减少进程间大数据传递并测量显示竞争；跟踪恢复帧还额外执行检测，需单独统计。保持两手每个有效推理帧都获得新结果，不以交替手、旧点重绘或摄像头帧率替代。

下一硬件版本应独立保存，复用已通过的 static，保留当前默认PL版本作为可回退发布。新增RTL应通过裁剪边界测试、原NNP逐块验证和双手视频回放，再进入物理实现；当前未因本评审自动启动新的布局布线。
